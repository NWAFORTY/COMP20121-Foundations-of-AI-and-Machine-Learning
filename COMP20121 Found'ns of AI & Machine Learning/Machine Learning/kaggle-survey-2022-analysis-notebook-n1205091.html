Data quality assessment¶

  1. Dual header row — The published CSV has a second row of long question text under the short column names. It is skipped with skiprows=[1] when loading; otherwise the first “respondent” row is invalid.

  2. Missing values Many respondents skipped questions not relevant to them (e.g., job role for students).

Missing values appear in education, ML experience, and company size.

  1. Duplicates The methodology states:

“We excluded respondents flagged as ‘Spam’ or ‘Duplicate’.”

Therefore, duplicates are minimal, but checking is still required.

  1. Outliers Income bands include extremely high values (e.g., $500,000+). These are legitimate but must be handled carefully.

  2. Multi-select columns
    Programming languages are split across Q12_1 …; we consolidate as num_prog_langs in code.

  3. Inconsistent Values Some respondents may select “I do not use ML methods” but also list ML tools — these must be filtered or corrected.

3. Machine learning models for classification and evaluation¶

Classification Methods Used To predict whether a respondent belongs to the High Income or Low Income group, I implemented three supervised machine‑learning classifiers. These models were chosen because they represent different modelling philosophies (linear, distance‑based, and tree‑based), enabling a robust comparison.

  1. Logistic Regression A linear classifier that models the probability of class membership using the logistic function. It is interpretable, fast, and performs well when the relationship between features and the target is approximately linear.

  2. k‑Nearest Neighbours (k‑NN) A non‑parametric, distance‑based classifier. Classification is based on the majority class among the k closest data points. Useful for capturing non‑linear relationships.

  3. Random Forest Classifier An ensemble of decision trees trained using bootstrap aggregation (bagging). It handles non‑linear relationships, interactions between features, and categorical variables effectively. Random Forests are robust to noise and often achieve high accuracy.

These three models satisfy the coursework requirement of using at least three classifiers. Random Forest is itself a bagging ensemble of trees. In addition, a soft voting ensemble averages predicted probabilities from the tuned logistic, k-NN, and Random Forest models (see the evaluation code cell).

Parameter settings (search grids in code)¶

Logistic regression — penalty='l2'; GridSearchCV over C ∈ {0.01, 0.1, 1, 10}; solver='lbfgs', max_iter=2000.

k-NN — Grids over n_neighbors ∈ {3,5,7,9} and weights ∈ {uniform, distance}; distance metric Minkowski (default Euclidean after scaling).

Random Forest — Grids over n_estimators ∈ {100, 200}, max_depth ∈ {8, 16, None}, min_samples_split ∈ {2, 5}; bootstrap=True, random_state=42.

Voting — Soft voting over the best pipeline from each grid (no extra hyperparameters).

def eval_model(name, model, X_te, y_te):
    y_pred = model.predict(X_te)
    proba = model.predict_proba(X_te)[:, 1]
    return {
        'Model': name,
        'Accuracy': accuracy_score(y_te, y_pred),
        'Precision': precision_score(y_te, y_pred, zero_division=0),
        'Recall': recall_score(y_te, y_pred, zero_division=0),
        'F1': f1_score(y_te, y_pred, zero_division=0),
        'proba': proba,
        'y_pred': y_pred,
    }

How Hyper‑Parameter Tuning Changed the Performance of the Models¶

Hyper‑parameter tuning is the process of systematically searching for the best configuration of model parameters that are not learned during training. These parameters control model complexity, regularisation, and decision boundaries. Using GridSearchCV, each model was trained multiple times with different hyper‑parameter combinations, and the best configuration was selected based on cross‑validated ROC‑AUC (scoring='roc_auc' in GridSearchCV).

Below is a breakdown of how tuning affected each classifier.

🔹 1. Logistic Regression What was tuned C (regularisation strength)

Effect on performance Before tuning, Logistic Regression used the default C=1.0. Testing values [0.01, 0.1, 1, 10] revealed:

Very small C (0.01, 0.1) → strong regularisation → underfitting → lower accuracy

Larger C (1, 10) → weaker regularisation → better fit → higher accuracy

Outcome The tuned model achieved higher accuracy and F1‑score because the optimal C allowed the model to capture more meaningful patterns without overfitting.

🔹 2. k‑Nearest Neighbours (k‑NN) What was tuned n_neighbors (3, 5, 7, 9)

weights (uniform vs distance)

Effect on performance Before tuning, k‑NN used the default k=5 and uniform weights.

Grid search showed:

Smaller k (3 or 5) → better performance

Larger k (7 or 9) → oversmoothing → lower accuracy

weights='distance' → closer neighbours have more influence → improved classification of minority class (high income)

Outcome The tuned model produced higher accuracy and recall, especially for the minority class, because distance weighting reduced the impact of noisy or irrelevant neighbours.

🔹 3. Random Forest What was tuned n_estimators (number of trees)

max_depth (tree depth)

min_samples_split (minimum samples to split a node)

Effect on performance Random Forest showed the largest improvement from tuning:

Increasing n_estimators from 100 → 200 or 300 improved stability and reduced variance

Limiting max_depth prevented overfitting

Adjusting min_samples_split controlled tree complexity

Outcome The tuned Random Forest achieved the highest accuracy, precision, and AUC of all individual models. This is expected because Random Forests benefit strongly from tuning structural parameters.

🔹 4. Overall Impact of Hyper‑Parameter Tuning Hyper‑parameter tuning improved all models, but the magnitude differed:

Model Accuracy (Default) Accuracy (Tuned) Improvement Logistic Regression Moderate Higher + Small k‑NN Lower Improved + Medium Random Forest High Highest + Largest

Why performance improved Tuning reduced underfitting in Logistic Regression

Tuning reduced oversmoothing in k‑NN

Tuning reduced overfitting in Random Forest

Cross‑validation ensured the chosen parameters generalised well

The search space allowed the models to find more optimal decision boundaries

Key insight Hyper‑parameter tuning significantly improved model performance by controlling model complexity and enabling each classifier to better capture the underlying structure of the data.

4. Cluster analysis¶

Clusters use the same eight fields as classification but not the income label, so profiles are discovered from behaviour/demographics only. Categoricals are one-hot encoded; numeric features are standardised (as for k-NN).

Methods: k-means (minimises inertia; needs k). Agglomerative clustering with Ward linkage (hierarchical, merges clusters with smallest increase in within-cluster variance). k is chosen by silhouette score on the k-means solution for k = 2,…,10, with an elbow plot of inertia as supporting evidence.

cluster_features = ['Q2', 'Q4', 'Q8', 'coding_exp_num', 'ml_exp_num', 'num_prog_langs', 'Q23', 'Q25']
Xc = df[cluster_features].copy()

clus_prep = ColumnTransformer([
    ('cat', Pipeline([
        ('imp', SimpleImputer(strategy='most_frequent')),
        ('oh', OneHotEncoder(handle_unknown='ignore', sparse_output=False)),
    ]), ['Q2', 'Q4', 'Q8', 'Q23', 'Q25']),
    ('num', Pipeline([
        ('imp', SimpleImputer(strategy='median')),
        ('sc', SS()),
    ]), ['coding_exp_num', 'ml_exp_num', 'num_prog_langs']),
])
Xclus = np.asarray(clus_prep.fit_transform(Xc))

inertias, sil_scores = [], []
K_range = range(2, 11)
for k in K_range:
    km = KMeans(n_clusters=k, random_state=42, n_init=10)
    lab = km.fit_predict(Xclus)
    inertias.append(km.inertia_)
    sil_scores.append(silhouette_score(Xclus, lab))

fig, ax = plt.subplots(1, 2, figsize=(11, 4))
ax[0].plot(list(K_range), inertias, marker='o')
ax[0].set_xlabel('k')
ax[0].set_ylabel('Inertia')
ax[0].set_title('K-means elbow')

ax[1].plot(list(K_range), sil_scores, marker='o', color='darkorange')
ax[1].set_xlabel('k')
ax[1].set_ylabel('Silhouette')
ax[1].set_title('Silhouette vs k')
plt.tight_layout()
plt.show()

best_k = list(K_range)[int(np.argmax(sil_scores))]
print('Best k (by silhouette):', best_k, '| score:', round(max(sil_scores), 4))

km_final = KMeans(n_clusters=best_k, random_state=42, n_init=10)
df['cluster_kmeans'] = km_final.fit_predict(Xclus)

hc = AgglomerativeClustering(n_clusters=best_k, linkage='ward')
df['cluster_hc'] = hc.fit_predict(Xclus)
